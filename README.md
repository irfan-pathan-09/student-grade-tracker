## Step-by-Step Development Process  

### 1. Idea and Project Planning
The first step of the project development process was selecting suitable CRUD-based projects for college submission. Two practical web application ideas were chosen:
•	Student Grade Tracker
•	Inventory Management System
The Student Grade Tracker was developed to manage student records, marks, and grades efficiently.
The Inventory Management System was created to manage inventory items for a small business or café-type environment.
These projects were selected because they provide real-world functionality while demonstrating important full-stack development concepts such as database handling, CRUD operations, frontend-backend communication, and deployment.
________________________________________
### 2. Generating the Base Projects Using Claude AI
To begin development quickly and efficiently, Claude AI was used to generate the initial base versions of both projects.
Claude AI helped create:
•	Basic project folder structures
•	Backend server setup using Node.js and Express.js
•	MongoDB database models
•	CRUD API routes
•	Simple frontend pages
•	Initial business logic for handling records
This provided a strong starting point for the development process and reduced the initial setup time.
________________________________________
### 3. Improving the Projects in Visual Studio Code
After generating the base versions, the projects were opened in Visual Studio Code (VS Code) for further development and improvement.
The Codex extension inside VS Code was used to improve different parts of the applications step by step.
Improvements included:
•	Better file and folder organization
•	Cleaner backend route handling
•	Improved MongoDB and Mongoose configuration
•	Enhanced frontend design and layout
•	Better form handling
•	Error handling implementation
•	Improved code readability and maintainability
•	Configuration optimization
This phase helped make the applications more structured, user-friendly, and easier to manage.
________________________________________
### 4. Backend Development
The backend for both applications was developed using:
•	Node.js
•	Express.js
RESTful API routes were created to perform CRUD operations:
CRUD Operations Implemented
•	Create new records
•	Read and display records
•	Update existing records
•	Delete records
Backend Responsibilities
Student Grade Tracker
The backend handles:
•	Student details
•	Grade records
•	Data storage and retrieval
•	Record management
Inventory Management System
The backend handles:
•	Inventory item management
•	Product data handling
•	Item updates and deletion
•	Inventory record maintenance
This backend structure ensured smooth communication between the frontend and database.
________________________________________
### 5. Database Setup
MongoDB was used as the primary database, while Mongoose was used as the Object Data Modeling (ODM) library.
The database setup included:
•	Creating database schemas and models
•	Establishing MongoDB connections
•	Managing data validation
•	Handling CRUD database operations
Environment variables were also used for secure configuration management, especially for:
•	MongoDB connection strings
•	Server configuration
•	Deployment settings
Example environment files were added to demonstrate setup configuration without exposing sensitive information.
________________________________________
### 6. Frontend Development
The frontend interfaces for both projects were created using:
•	HTML
•	CSS
•	JavaScript
The frontend was connected to backend APIs to allow users to interact with the applications.
Features Implemented
Users can:
•	Add records
•	Edit records
•	View records
•	Delete records
The interface was designed to remain simple, clean, and user-friendly.
________________________________________
### 7. Local Testing and Debugging
Before deployment, both applications were tested locally on the development system.
Required npm packages were installed, and the projects were executed using Node.js commands.
Testing Checklist
The following functionalities were tested:
•	Server startup
•	Frontend loading
•	Database connectivity
•	Record creation
•	Data display
•	Record updates
•	Record deletion
•	API functionality
This testing phase helped identify and fix issues before deployment.
________________________________________
### 8. Using Git for Version Control
Git was used to manage version control and track changes throughout development.
Git repositories were initialized for both projects, and changes were committed regularly.
Common Git Commands Used
git init
git add .
git commit -m "Initial project commit"
Using Git helped maintain project history and improve project management.
________________________________________
### 9. Uploading Projects to GitHub
After local development and testing, GitHub repositories were created for both projects.
The local repositories were connected to GitHub and pushed online.
Steps Followed
1.	Create a new repository on GitHub
2.	Copy the repository URL
3.	Add remote origin
4.	Push project files to GitHub
This allowed the projects to be safely stored online and prepared for deployment.
________________________________________
### 10. Deploying the Projects on Railway
Both projects were deployed using Railway.
The deployment process included:
•	Connecting GitHub repositories with Railway
•	Configuring environment variables
•	Installing project dependencies automatically
•	Running the application start scripts
Environment Variables Configured
•	MongoDB connection string
•	Server port settings
Railway successfully hosted both applications online.
